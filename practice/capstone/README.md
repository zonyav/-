# Итоговый проект: RAG-ассистент по базе знаний

Это не макет ответа, а небольшой воспроизводимый проект. Он читает Markdown/TXT-документы, создаёт локальный индекс embeddings, ищет релевантные фрагменты, применяет порог ответа, показывает источники и считает retrieval-метрики. Генератор подключается через любой совместимый Chat Completions API; без ключа проект продолжает работать как смысловой поиск и показывает готовый prompt.

## Что вы построите

```text
документы → очистка → chunks → embeddings → top-k → answerability gate
                                                       ↓
                                    источники ← ответ или честный отказ
```

## Быстрый запуск

Нужен Python 3.10 или новее. Первый запуск скачивает embedding-модель и требует интернет.

```text
python -m venv .venv
.venv\Scripts\activate
python -m pip install -r requirements.txt
python ingest.py
python evaluate.py
python -m unittest
streamlit run app.py
```

На macOS/Linux команда активации: `source .venv/bin/activate`.

## Подключение генератора — необязательно

Скопируйте `config.example.env` в `.env` и заполните адрес, имя модели и ключ для выбранного совместимого API. Не загружайте `.env` в публичный репозиторий.

Если переменные не заполнены, интерфейс всё равно покажет retrieval, scores, источники и prompt. Это полезно: сначала можно доказать качество поиска, не расходуя платные вызовы.

## Как заменить учебные документы своими

1. Удалите примеры из `documents` и добавьте 5–30 файлов `.md` или `.txt` одной предметной области.
2. Не используйте секреты и персональные данные без разрешения и защиты.
3. Удалите папку `index`, если она осталась от прежнего корпуса, затем снова запустите `python ingest.py`.
4. Перепишите `eval.jsonl`: реальные вопросы, ожидаемый файл и признак наличия ответа.
5. Запустите `python evaluate.py` до изменения prompt.

## Что измеряется

- `Recall@3`: встретился ли ожидаемый документ среди первых трёх результатов;
- `Top-1 accuracy`: оказался ли ожидаемый документ первым;
- `Answerability accuracy`: правильно ли система решила отвечать или отказаться;
- время retrieval для каждого вопроса;
- распределение top score для вопросов с ответом и без ответа.

Порог в учебном проекте не универсален. Настройте его на собственном eval-наборе и цене двух ошибок: ложного ответа и лишнего отказа.

## Структура

- `rag_core.py` — chunking, индекс, retrieval, prompt, optional LLM и безопасный журнал;
- `ingest.py` — построение индекса;
- `evaluate.py` — воспроизводимая проверка;
- `test_rag_core.py` — unit-тесты chunking, retrieval и сборки prompt;
- `app.py` — интерфейс Streamlit;
- `documents` — демонстрационные документы;
- `eval.jsonl` — вопросы с эталонами;
- `project_report.md` — отчёт и материалы защиты;
- `Dockerfile` — повторяемая упаковка приложения.

## Контрольные эксперименты

1. Сравните `CHUNK_SIZE=500` и `CHUNK_SIZE=900` на одном eval.
2. Добавьте пять перефразированных запросов и посмотрите, падает ли Recall@3.
3. Добавьте два вопроса без ответа и откалибруйте threshold.
4. Найдите три retrieval miss и классифицируйте причину.
5. Подключите генератор и отдельно оцените наличие ссылок и поддержку утверждений источниками.
6. Измерьте задержку и цену на 20 запросах.

## Готовность проекта

Проект готов к защите, когда другой человек запускает его по README, eval воспроизводится, источники открываются, unanswerable-вопросы приводят к отказу, а в отчёте честно описаны слабые случаи и следующий эксперимент.
